# 项目简介：LumeLog
>
> 面向工控和嵌入式测试的下一代日志与 CAN 报文查看器，基于 Tauri + Rust 构建

## ✨ 项目定位

LumeLog 不是“另一个 Notepad++”，而是面向工控和嵌入式测试的下一代日志与 CAN 报文查看器。它在通用编辑能力上对标 Notepad++，在大日志、工控编码、DBC 解析、跨平台支持上超越 Notepad++。
坚持**技术中立**，软件本身只承担工程工具职责，不附加任何无关内容。

## 🎯 解决痛点

1. **超大日志文件加载**：台架、HIL 测试经常产出数 GB 级别的连续日志，很多编辑器卡顿、假死、无法打开；
2. **工控编码兼容**：原生良好支持 GBK / GB2312 / UTF-8 / UTF-16，适配国内工业设备、ECU 导出日志的老旧编码；
3. **CAN 报文快速解析**：内置 DBC 解析能力，一键解析 CAN/CAN FD 日志，报文可视化、过滤、正则提取；
4. **轻量快速**：启动快、资源占用低，保留经典轻量记事本类编辑器的简洁体验；
5. **跨平台支持**：同时适配 Windows / Linux / macOS，统一体验，摆脱平台绑定限制。

## 🛠 技术栈

- 后端核心：Rust
- 跨端框架：Tauri v2
- 解析模块：自定义 CAN 日志、DBC 解析器
- 脚本扩展：内置简易脚本能力，用于自动化日志清洗、批量导出

## 📌 和同类工具差异

- VS Code：功能全面，但体积大、启动开销高，打开巨量日志容易资源暴涨；
- Notepad++：Windows 独占，生态成熟，但存在非技术内容夹带问题；
- Sublime Text：闭源商业软件，缺少原生工控报文解析能力；
- Notepad--：同类替代项目，但大文件性能、CAN 场景支持尚有短板。

> 工业调试（嵌入式、商用车动力电控、HIL 自动化测试）是优先做强的场景：超大日志、工控编码、报文解析是区别于其他通用编辑器的立足点。
> 次要受众是互联网工程师：前端 TypeScript + CodeMirror + Vite，后端 Rust，可直接参与开发。贡献不限定语言，Office 工具链之类的周边也欢迎。
